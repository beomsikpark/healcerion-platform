# Moana — Qt 앱과 호스트 SW 3종 대조

> **근거**: `client/legacy/moana` **`origin/service_QT693`**(HEAD 2026-07-27) 코드 직접 읽기 + `cuattro-sdk`·`sonex-app` 대조(2026-07-27).
> **⚠ master 를 보면 안 된다** — `master` 는 2022-02-17 에 멈춰 있고 실제 개발은 `service_QT693` 에서 오늘까지 이어진다.
> **관련**: [sonex-app.md](sonex-app.md)(진행 중인 재작성) · [device-firmware.md §8](device-firmware.md)(프로토콜)

## 0. Moana 는 대체되는 구세대가 아니다

"Moana(Qt) → sonex(Flutter) 전환" 이라는 통념과 달리, 코드로 보면 **Moana 가 더 성숙하고 더 넓다.**

| | **Moana** | `sonex-app` + `sonex-framework` |
|---|---|---|
| 실제 타깃 | **6개** — Android · iOS · Windows · **UWP** · macOS · Linux(x64 + **arm64**) | 4개 (linux·web 은 stub) |
| 지원 모델 | **8종** — 300C · 310C · 300MC · 300VC · 300L · 300PA · 500L · **FUJI_L43K** | **5종** — 300C · 300L · **500C** · 500L · **500P** |
| 자체 코드 | C++ 142.5k + QML 85k LOC | Dart 69k + C++ 119k(SDK+ADK) |
| 최종 커밋 | **2026-07-27** | 2026-07-15 / 2026-07-23 |
| 계층 분리 | `framework`(static lib) ↔ `app`(QML), **역의존 6건**(아래 주) | ADK→SDK 단방향(양호) / 앱은 구·신 패턴 혼재 |

> **정정(2026-07-28)**: 이전 판은 "역의존 없음" 이라 적었으나 **실측 결과 6건 있다.** `framework/framework.pro:269` 이 `INCLUDEPATH += $$PWD/../app/Sources` 를 올리고, `SononClient/{CtrlChannel,SononCtrlPacket,SononDataPacket}.cpp` · `Record/{RecordFileWriter,BackupFileReader}.cpp` 가 `Common/AppSetting.h` 를, `Database/DataManager.cpp:15` 가 `common/AppUtility.h` 를 include 한다. 헤더 basename 중복이 0건이고 `framework/Common/` 에 두 헤더가 없으므로 전부 `app/Sources/Common/` 을 가리킨다.
>
> **다만 475파일 대비 6건은 작다** — 2계층 규율이 대체로 지켜졌다는 §3 의 평가 자체는 유지된다. 상세·처리 계획 = [../refactoring/r1/phase2-layer-boundary.md](../refactoring/r1/phase2-layer-boundary.md).

> **정정 (2026-07-29) — 모델 목록이 틀렸다.** 이전 판은 moana 를 **10종(500C·500P 포함)** 으로 적었다. **실측하면 `app/Sources/Common/Model.cpp` 의 `modelName ==` 분기 + `InitCapabilityTable_*` 가 8종뿐이고 500C·500P 가 없다.** 그 둘은 `framework/Common/CommonData.cpp:71,73` 의 `deviceModelList` 문자열 목록에만 있다(700C·700L 도 함께) — **이름만 알고 구동하지 못한다.**
>
> **따라서 두 앱의 모델 집합은 부분집합이 아니라 교집합이다.**
>
> | | 모델 |
> |---|---|
> | 공통 3종 | 300C · 300L · 500L |
> | **moana 전용 5종** | 310C · 300MC · 300VC · 300PA · FUJI L43K |
> | **`sonex` 전용 2종** | **500C · 500P** |
>
> 이 오류가 [../refactoring/r1/phase10-runtime-variant.md](../refactoring/r1/phase10-runtime-variant.md) §2.1 로 전파됐고 함께 정정했다. 판단에 미치는 영향 = [../refactoring/moana-vs-sonex.md §3.1](../refactoring/moana-vs-sonex.md).

**둘 다 현재 활발하다.** "전환" 이 아니라 **병행 유지**로 보는 것이 코드에 부합한다. 판단 대기 1번(sonex 전환과의 중복 관계)이 여기서 갈린다.

## 1. 9.4GB 의 정체 — 자체 소스는 0.1% 미만

| 버킷 | 크기 | 비중 |
|---|---:|---:|
| **`lib/` 벤더 프리빌트 바이너리** | **6.56G** | **97.7%** |
| `.git` | 3.13G | — |
| `app/`(소스+리소스) | 73.9M | 1.1% |
| `test/`(수동 테스트 앱 + 2018년 녹화 샘플) | 63.3M | 0.9% |
| `framework/`(전부 소스) | 2.8M | 0.04% |

`lib/` 내역 — **플랫폼 7종(android·ios·iossimulator·linux·linux_arm64·macos·windows)별로 각각 빌드**돼 있다.

| 라이브러리 | 크기 |
|---|---:|
| DCMTK 3.6.3/3.6.4/3.6.5 | 2.06G |
| OpenCV 3.4.5/3.4.6/3.4.9 | 1.85G |
| FFmpeg 4.0.2/4.1/4.1.4/4.2.3 | 0.95G |
| TensorFlow Lite (bazel 산출물) | 0.94G |
| wxSQLite3 / CipherSqlitePlugin | 234M — **Qt5 시절 5개 버전분(5.12.4·5.14·5.15·5.15.2·5.15.7)이 Qt6 이행 후에도 그대로** |
| ContextVision cvie | 113M |
| OpenSSL 4개 버전 | 97M |

최대 단일 파일은 `lib/ios/opencv2.framework/opencv2` **292MB**. `.git` 3.13GB 는 이 바이너리들을 5,705커밋에 걸쳐 갱신한 결과다(델타 압축이 듣지 않는다).

**실제 자체 소스는 8MB 미만**이다. sonex-framework 의 2.0GB 중 자체 소스 0.3% 와 같은 병리이되 규모가 3배다.

## 3. 구조 — 2계층이 지켜진다

```
moana.pro                       SUBDIRS = app, framework   (app.depends = framework)
framework/   ← static lib libframework.a — "코어 SDK"
  SononClient/    HC 프로토콜 클라이언트 (Base/Ctrl/Data 채널 + 패킷 프레이밍)
  Include/        SononCommon.h — 프로토콜·장비 상수
  ImageProc/      ImageFilterSetting, HCNextSRIFilter (OpenCL/UMat)
  ContextVision/  cvie SDK 래퍼
  Dicom/          UnifiedDicomAdapter (DCMTK, C-STORE/워크리스트)
  Database/       암호화 SQLite (wxSQLite3/cipher)
  Record/         BackupFile*/RecordFile* — 자체 "HEAL" 태그 녹화 포맷
  Network/ Platform/ ScanManager/ AudioProc/ VideoProc/ TensorFlow-Lite/ Ambulance/
app/         ← QML UI + C++ 뷰컨트롤러
  Sources/{Main,Scan,Measure,DeviceControl,Common,PatientList,WorkList,Cloud,Ambulance,BLE,Setting,Test}
  Resources/{QML,Images,Font,Language,ContextVision,Model,Shaders,HCUIKit}
  Android/ iOS/ UWP/
```

**장비 접근이 완전히 격리돼 있다** — UI·도메인 로직이 소켓을 직접 만지지 않고 `app/Sources/DeviceControl/ControlCommand` → `framework/SononClient` 를 거친다. sonex 의 SDK/앱 분리와 같은 형태이고, **이쪽이 먼저다.**

## 5. 필터가 sonex 와 1:1 포팅이다 — 그들 문서가 그렇게 적었다

저장소 안 `docs/NextSRI_vs_Sonex_Comparison.md` 가 `sonex-framework` 의 `sdk/ImageFilter/shared/filter/HCSRIv20_5Filter` 와 **1:1 포팅이며 바이트 단위로 검증**했다고 기록한다. 기능 차이는 둘뿐 — **UMat/OpenCL(Moana) vs Mat/CPU(sonex)**, 그리고 EPF 비활성화.

즉 **두 앱이 핵심 영상 알고리즘을 공유하되 각자 포팅해 유지한다.** ContextVision(cvie) 대체 작업(`NextSRI`)이 양쪽에서 따로 진행 중이다.

## 6. 호스트 SW 3종 대조 — 프로토콜 계보가 갈렸다

| | `moana` | `cuattro-sdk` | `sonex-framework` |
|---|---|---|---|
| 언어·UI | C++/Qt QML | C++ DLL + **C# WinForms** | C++ SDK (UI 없음) |
| 프로토콜 선언 | **`COMMON_PACKET_HEADER`** 원본 | **moana 의 포크** | 자체 상수(`HC_PACKET_*`) |
| `SononClient` 파일 | 17개 | **15개가 동명**(내용 분기) | — |
| 지원 모델 | **8종**(500C·500P 없음) | 300C·300L 뿐 | 5종(**500C·500P 포함**) |
| 최종 | 2026-07-27 | 2018-12 | 2026-07-23 |

`cuattro-sdk/SononClient/` 의 `BasePacket`·`BaseSocket`·`CtrlChannel`·`DataChannel`·`SononClient`·`SononCtrlPacket`·`SononDataPacket`·`SononPacket` 이 전부 moana 와 동명이다. "Cuattro 용 window SDK **C# 포팅**" 의 실체는 **moana `framework/SononClient` 를 떼어내 Windows DLL 로 만들고 C# 래퍼를 씌운 것**이다. Cuattro 자체는 별도 제품이 아니라 `#ifdef HAVE_CUATTRO` 브랜딩 스위치다.

→ **동일 프로토콜 클라이언트가 최소 3벌 병행 유지**되고 있다. 리팩토링에서 통합 효과가 가장 큰 표면이다.

## 9. 최근 개발(최근 60커밋, 2025-12-30 ~ 2026-07-27)

**유지보수 국면**이다. 신규 기능이 아니라 회귀 수정이 지배적이다.

- **측정·리뷰 회귀** (최대 군집) — VOL(BloodVolumeFlow) 측정값이 모드 전환 시 사라짐, 듀얼 M-mode 에서 Length 도구 누락, 캡처·리뷰 시 GL 좌표 불일치
- **스캔 모드 전환 버그** — CF→PW / B→PW,M 캡처 시 썸네일·프리셋 오류, CF ROI 박스 흔들림, **FPS 10~25 널뜀**
- **Android 16KB 페이지 크기 대응** — Qt 미디어 백엔드가 번들하는 4KB 정렬 FFmpeg 과 충돌. 전용 문서 2건 + `QT_MEDIA_BACKEND=android` 우회
- **NextSRI V1.20.5 롤아웃** — CVIE/HNS 라이선스 분기
- **릴리스 사무** — M2.03.24 → M2.03.26(빌드 118→127). `HC_RELEASE_TARGET` 미설정 시 qmake 가 **hard-error** 내도록 강제(M2.03.24 에서 CE/US 빌드가 뒤바뀌어 출하된 사고 재발 방지)
- **PACS** — 업로드 이미지 사선 밀림 수정(2026-07-22)

마지막 항목이 시사적이다 — **릴리스 타깃을 잘못 지정해 출하한 사고**가 있었고, 그 대응이 빌드 시스템의 hard-error 였다. 변종 관리 방식(§7)의 비용이 실제로 발생했다는 증거다.

## 11. 미확인

- Moana 와 sonex 의 **제품상 관계** — 병행 판매인지, 시장·모델별 분담인지. 코드로는 판정 불가
- `framework/SononClient` 3벌 사이의 실제 기능 차이 — 파일명만 대조했고 내용 diff 는 하지 않았다
- `Ambulance` 기능의 현재 운영 여부 — 앱 측은 14.9k LOC 인데 서버 측은 39줄 프로토타입뿐이다
- `FUJI_L43K` 모델 — `fpga/legacy/fuji-oem-us-fpga` 와의 대응 관계 미확인
