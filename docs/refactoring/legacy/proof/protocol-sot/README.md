# 실증 — HC 프로토콜 정본 1벌

**주장이 아니라 실물이다.** 힐세리온 코드에서 원본 선언 3벌을 읽어 정본 1벌을 만들고, 그것이 원본과 같다는 것을 **컴파일러가 판정하게** 했다.

```bash
make            # 생성물 최신 확인 + 증명 실행
make report     # 원본 3벌의 차이 보고서
```

`make` 가 통과하면 아래 셋이 참이다.

| # | 증명한 것 | 방법 |
|---|---|---|
| 1 | **14바이트 배치가 원본 3벌과 정본에서 동일하다** | `_Static_assert` 로 필드 6개의 offset·width·구조체 크기 대조 |
| 2 | **양쪽 코드베이스가 오늘 그대로 컴파일된다** | 원본 철자 **198개**가 `hc_protocol.h` 만으로 **원래 값**으로 해석됨을 정적 단언 |
| 3 | **동작이 보존된다** | 장비가 만든 실제 응답 바이트를 앱의 검증 로직에 그대로 통과시킨다 |

2번이 핵심이다. **정본 도입이 호출부를 한 줄도 바꾸지 않는다** — 이름을 지우는 것은 헤더가 양쪽에 들어간 뒤의 별개 작업이다. 의료기기 코드에 넣는 첫 변경이 "값도 이름도 동작도 그대로"라는 뜻이다.

## 무엇을 입력으로 썼나

원본은 **옮겨 적지 않았다.** 커밋 SHA 로 고정한 미러에서 `reconcile.py` 가 직접 읽는다 — 옮겨 적는 순간 "원본과 같다"는 주장이 근거를 잃기 때문이다.

| 역할 | 저장소 | 커밋 | 파일 |
|---|---|---|---|
| 장비 (belle 500L, 출하중) | `belle-fw` | `b6aaa3d41d2a` (`production-fw-ver2.0`) | `sonon/sonon_receive.h:2210-2217` |
| 클라이언트 (Qt, 출하중·사양 SOT) | `moana` | `7b26a9b27219` (`service_QT693`) | `framework/SononClient/SononPacket.h:138-146` |
| 장비 (500C, **범위 밖 — 기록만**) | `500c-sn-fw` | `ca2096a26bb1` (`FW_1_1_8_0`) | `src/App/include/USSCustomCommand.h:3029-3036` |

`include/hc_protocol.h` · `vendored/` · `compat_test.c` 는 **전부 생성물**이다. `make check` 가 원본과 어긋나면 실패한다 — CI 게이트가 이것이다.

## 원본 3벌이 실제로 얼마나 갈라져 있나

`make report` 의 결과다. 대조 범위는 `packet_type` · `DEVICE` opcode · `FPGA` opcode · `target_id` 네 공간이다.

| | belle | moana | 500C |
|---|---:|---:|---:|
| 선언한 상수(값 기준) | 130 | 66 | 136 |

belle ∪ moana = **138개 값**. 그 138개가 두 코드베이스에서 어떻게 만나는가:

| 분류 | 건수 | 뜻 |
|---|---:|---|
| **같은 값, 공유하는 이름이 하나도 없음** | **41** | 같은 명령을 장비와 앱이 다른 이름으로 부른다 |
| 이름까지 일치 | 15 | |
| 장비만 선언 (앱에 상수 없음) | 72 | 앱에서 이름으로 도달할 수 없는 장비 기능 |
| 앱만 선언 (장비에 상수 없음) | 8 | 500C/SN 전용 — belle 에 대응 없음 |
| **같은 이름이 코드베이스마다 다른 값** | **0** | **병합이 안전한 이유.** 이름 충돌이 없으므로 별칭 통합이 무손실이다 |

마지막 줄이 이 작업을 지금 할 수 있게 만든다. **같은 이름이 두 가지를 뜻하는 지점이 하나도 없다** — 그래서 원본 철자를 전부 별칭으로 남기는 통합이 성립한다.

41건의 예:

| 값 | 장비 | 앱 |
|---|---|---|
| `0x0101` | `FPGA_WRITE_DEPTH` | `FPGA_DEPTH` |
| `0x0110` | `FPGA_READ_PROBE_TYPE` | `FPGA_PROBE_TYPE` |
| `0x0118` | `FPGA_WRITE_DTGC_CTRL` | `FPGA_TGC` |
| `0x020A` | `FPGA_WRITE_SCAN_SAMPLES` | `FPGA_SAMPLE_512` |
| `0x0100` | `HER_PACKET_TYPE_B_ONLY_SCAN_DATA` | `HC_PACKET_TYPE_SCAN_DATA` · `HC_PACKET_TYPE_B_MODE` |

> [../../../review/protocol-device.md](../../../review/protocol-device.md) §6.3 은 `FPGA_READ_PROBE_TYPE 0x0110` 을 "양쪽 일치"로 적었으나 앱은 `FPGA_PROBE_TYPE` 이다. 기계 대조에서 드러난 오류이며, 손으로 고른 표본과 전수 대조의 차이가 이것이다.

## `recv_id` — 선언이 갈려서 이미 생긴 결함

**단순한 이름 문제가 아니라는 증거다.**

| | 모델 | 코드 |
|---|---|---|
| 장비 | `U16` | `belle-fw/sonon/sonon_receive.cpp:79` — `header->recv_id = HER_TARGET_ID_CLIENT;` |
| 앱 | `char[2]` | `moana/framework/SononClient/BasePacket.cpp:731` — `if (m_pkt_head->recv_id[1] == target_id)` |

리틀엔디언에서 장비는 target 을 **바이트 0** 에 넣는다(`{0x02, 0x00}`). 앱은 **바이트 1** 을 본다. `target_id` 는 1 아니면 2 이므로 **이 검사는 절대 성립할 수 없다** — 죽은 코드다.

**지금 동작은 맞다.** 실제 target 검증은 그 위의 `memcmp(head, context, 6)` 이 우연히 `recv_id[0]` 까지 덮어서 이뤄지고 있다. 즉 **의도한 검사는 죽어 있고 부수 효과가 그 자리를 대신하고 있다.** memcmp 길이를 손대거나 필드를 재배치하는 순간 target 검증이 조용히 사라진다.

`verify_layout.c` 가 이것을 실행으로 보여준다 — 장비 인코딩 → 앱 검증 로직 → 통과, 그리고 `recv_id[1]=0x00` vs `target_id=0x02`.

> 이것은 **활성 버그가 아니라 잠복 결함**이다. 그 구분을 유지한다.

## 정본이 택한 규약

| 항목 | 선택 | 이유 |
|---|---|---|
| opcode 이름 | **belle 의 `READ`/`WRITE` 명시형** | 더 완전하고(FPGA 83 vs 36) 이름만으로 방향이 읽힌다 |
| 원본 철자 | **전부 별칭으로 보존** | 호출부를 바꾸지 않는 것이 도입 조건이다 |
| `recv_id` | `uint16_t` (장비 모델) | 송신 측 모델을 따른다. 앱의 바이트 접근은 별칭이 아니라 **수정 대상**으로 남긴다 |
| 500C | **병합하지 않고 주석으로 기록** | 정본 대상은 belle+moana 였다. 차이만 헤더 하단에 남긴다. **단 "범위 밖" 의 근거였던 단종 판정은 2026-07-29 에 철회됐다**([r1/phase10 §1.6](../../r1/phase10-runtime-variant.md)) — **재검토 대상** |

## 남는 것 — 이 산출물이 답하지 않는 것

- **엔디언이 명시적으로 변환되지 않는다.** 양쪽 다 리틀엔디언 호스트라 성립하고 있을 뿐이다
- **CRC 가 없다.** 함수명은 `verify_packet_header_and_crc` 인데 검사 코드가 없다(원본 그대로)
- `PACKET_DATA_U` 본문 페이로드 레이아웃은 이번 범위 밖이다 — 헤더와 opcode 까지만 다뤘다
- 이 헤더를 실제 두 저장소에 **넣는 것**은 힐세리온 승인 사항이다. 여기서는 넣을 수 있음을 증명만 했다

## 배치에 대해

지금 위치(`docs/refactoring/proof/`)는 **검토 근거물**로서의 자리다. 정식 산출물이 되면 컨테이너 최상위의 공유 계층으로 옮겨간다 — 그 축을 만드는 것은 별도 판단이다(루트 `CLAUDE.md` §폴더 구조).
