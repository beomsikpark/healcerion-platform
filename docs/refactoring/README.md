# 리팩토링 검토

**힐세리온 시스템을 인수해 cctv-platform 수준의 플랫폼으로 만든다.** 코드 정리가 목적이 아니라 그 결과물이 목적이다.

현행 구조 분석은 [../review/](../review/) 가 SOT 이고, 여기는 그 위에서 **무엇을 만들 것인가 · 왜 · 어떤 순서로** 를 다룬다.

## 만들 것 — 다섯이 서로를 필요로 한다

| # | 구성 | 지금 |
|---|---|---|
| 1 | **feature-first clean architecture** — device·client 양쪽이 **같은 feature 이름**을 쓴다 | 장비는 기술 역할로 잘려 있고, sonex 는 **도메인 이식 0건**인데 구 계층은 자란다 |
| 2 | **빌드 가능한 소스** — 깨끗한 체크아웃 → 1커맨드 → 이미지 | 절대경로 `/home/jacob/...` 의존, 커널 모듈 3종 Makefile 부재 |
| 3 | **로컬 에뮬레이터** — 실장비 0대로 전 경로 실행 | 포트 추상화는 있는데 **선택이 하드코딩**돼 쓸 수 없다 |
| 4 | **E2E + CI** — 회귀를 커밋 시점에 잡는다 | CI **31개 저장소 전부 0건** |
| 5 | **플랫폼 뼈대** — 정본 프로토콜 · 표준 CLI · 공유 계층 | 프로토콜이 **7개 코드베이스에 복제**, 선언만 3벌 |

빌드가 돼야 에뮬레이터가 돌고, 에뮬레이터가 있어야 E2E 가 CI 에서 돌고, feature 로 나뉘어야 테스트가 국소적이며, 정본이 하나여야 축 사이가 이어진다.

## 두 가지 목적

| 목적 | 무엇으로 달성되는가 |
|---|---|
| **다방면에서 경쟁력을 갖는 플랫폼** — 장비·앱·클라우드가 한 플랫폼으로 움직인다 | **1·5** 가 축을 잇고, **2·3·4** 가 변경 속도를 만든다 |
| **AI 가 다룰 수 있는 코드베이스** | **1** 이 컨텍스트를 좁히고, **2·3·4** 가 **검증 루프**를 닫는다 |

두 번째는 부수 효과가 아니라 설계 목표다. 지금 AI 는 읽고 제안만 할 수 있다. **고치고 → 빌드하고 → 실행하고 → 판정하는 루프**가 서면 유지보수 생산성의 대부분이 여기서 갈린다 — 그리고 이 조건은 **사람이 유지보수하기 좋은 조건과 정확히 같다**. 상세 = [why.md §2](why.md).

## 핵심

**기능 하나를 바꾸려면 3개 저장소·10개 이상 파일을 건드려야 하고, 고쳤는지 확인할 방법이 없다.**

| 시나리오 | 지금 | 목표 |
|---|---|---|
| PW 파라미터 1건 추가 | 장비 6파일 + 프로토콜 3벌 + 앱 2벌 | **3곳** |
| 측정 도구 추가 | `scan_controller.dart` **8,354 LOC** 수정(sonex) | feature 1개 |
| 새 모델 지원 | 컴파일 플래그 + 모델별 별도 빌드 | **런타임 설정 1건** |
| 고쳤는지 확인 | 실장비 연결 → 수동. **회귀를 고객이 발견** | 개발 PC E2E |

## 힐세리온이 얻는 것

| | 실측 |
|---|---|
| **멈춘 일이 끝난다** | Qt→Flutter 전환 2년 3개월간 **도메인 이식 0건**이고 구 계층은 1년에 4.6배 · 장비 밑단 2021년 동결 |
| **회귀가 출하 전에 잡힌다** | 개발팀 수정 목록과 CS 티켓이 **같은 주제**(T8777·T8807·T9153) |
| **출시가 빨라진다** | 모델별 빌드 → 단일 이미지. CE/US 뒤바뀜 출하 사고가 구조적으로 제거 |
| **규제 산출물이 부산물로 생긴다** | 62304 구성관리·SOUP·검증기록 = CI·의존성 관리의 결과물 |
| **지식이 저장소에 남는다** | 지금 빌드 절차는 특정 디렉토리 배치(`/home/jacob/...`)에 들어 있고 README 0건 |

## 지금 착수 가능 (병렬)

| 항목 | 이유 |
|---|---|
| **프로토콜 정본 단일화** | 선언 3벌·명명 불일치. 빌드 재현을 기다리지 않는다. **에뮬레이터의 첫 소비자**이기도 하다 |

| **비밀정보 교체 · `sdi`/`ela` DDL** | 사업 연속성. 시간 단위 작업 |

`.xsa` Vivado 프로젝트는 **하드웨어 변경 시** 필요하고 빌드 재현의 전제가 아니다 — `psu_init_gpl.c` 가 소스로 있고 U-Boot SPL 이 이미 빌드된다.
