# 리팩토링 검토

**힐세리온 시스템을 위탁 리팩토링해 cctv-platform 수준의 플랫폼으로 만든다.** 코드 정리가 목적이 아니라 그 결과물이 목적이다. 소유권은 힐세리온에 남는다.

> **이 갈래는 우리 판단 기록이다.** 힐세리온에 제출하는 문서는 [../proposal/](../proposal/) 하나이고, 여기 있는 정정 기록·내부 논의는 그쪽에 넣지 않는다.

> **전제 둘 — 이것을 빼고 읽으면 논지가 서지 않는다**
>
> **① 작업자는 AI 에이전트다.** 사람이 코드를 직접 쓰는 것을 전제로 한 계획은 성립하지 않는다. 작업량의 상한이 인원이 아니라 **AI 가 안전하게 만질 수 있는 코드 표면**으로 바뀐다 — [why.md §1](why.md).
>
> **② 예측이 아니라 재현이다.** 같은 팀이 동종 시스템(cctv-platform)에서 같은 방법으로 이미 끝냈고, **2026년 커밋의 91% 를 AI 가 처리**하고 있다 — [precedent-cctv.md](precedent-cctv.md).

현행 구조 분석은 [../review/](../review/) 가 SOT 이고, 여기는 그 위에서 **무엇을 만들 것인가 · 왜 · 어떤 순서로** 를 다룬다.

## 만들 것 — 다섯이 서로를 필요로 한다

| # | 구성 | 지금 |
|---|---|---|
| 1 | **feature-first clean architecture** — device·client 양쪽이 **같은 feature 이름**을 쓴다 | 장비는 기술 역할로 잘려 있고, sonex 는 **도메인 이식 0건**인데 구 계층은 자란다 |
| 2 | **빌드 가능한 소스** — 깨끗한 체크아웃 → 1커맨드 → 이미지 | 절대경로 `/home/jacob/...` 의존, 커널 모듈 3종 빌드 파일 부재 |
| 3 | **로컬 에뮬레이터** — 실장비 0대로 전 경로 실행. **별도 산출물이 아니라 `platforms/pc` 어댑터** | 포트(`DEVICE_EBI`/`DEVICE_DUMMY` vtable)는 있는데 **선택이 하드코딩**돼 쓸 수 없다 |
| 4 | **E2E + CI** — **데이터 경로 회귀**를 커밋 시점에 잡는다 | CI **31개 저장소 전부 0건** |
| 5 | **플랫폼 뼈대** — 정본 프로토콜 · 표준 CLI · 공유 계층 | HC 프로토콜이 **저장소 9곳에 흩어져 있고** 구조체 선언만 3벌 |

빌드가 돼야 에뮬레이터가 돌고, 에뮬레이터가 있어야 E2E 가 CI 에서 돌고, feature 로 나뉘어야 테스트가 국소적이며, 정본이 하나여야 축 사이가 이어진다.

**다섯 전부 cctv-platform 에 실물이 있다** — 카메라·녹화장치 앱이 각각 feature 27개이고 **이름 21개를 공유**한다 · `platforms/ubuntu24` 가 곧 에뮬레이터 · 제품 23종 단일 defconfig 트리 · E2E 시나리오 40개 · `make` 인터페이스 통일. 설계안이 아니라 재현이다([precedent-cctv.md](precedent-cctv.md)).

## 두 가지 목적

| 목적 | 무엇으로 달성되는가 |
|---|---|
| **다방면에서 경쟁력을 갖는 플랫폼** — 장비·앱·클라우드가 한 플랫폼으로 움직인다 | **1·5** 가 축을 잇고, **2·3·4** 가 변경 속도를 만든다 |
| **AI 에이전트가 작업을 끝낼 수 있는 코드베이스** | **1** 이 컨텍스트를 좁히고, **2·3·4** 가 **검증 루프**를 닫는다 |

두 번째는 부수 효과도, 설계 취향도 아니라 **전제**다. 작업자가 AI 이므로 작업량의 상한이 인원이 아니라 코드 표면으로 정해진다. 지금 AI 는 읽고 제안만 할 수 있다 — **고치고 → 빌드하고 → 실행하고 → 판정하는 루프**가 서야 작업이 닫힌다. 그리고 이 조건은 **사람이 유지보수하기 좋은 조건과 정확히 같다**. 상세 = [why.md §1](why.md).

## 핵심

**기능 하나를 바꾸려면 3개 저장소·10개 이상 파일을 건드려야 하고, 고쳤는지 확인할 방법이 없다.**

**그리고 그 비용은 실측됐다** — 아래는 투영이 아니라 그들 git 이력에서 잰 값이다([../review/change-cost.md](../review/change-cost.md)).

| 실측 | 값 |
|---|---|
| 기능 1건(Power Doppler)이 출하되기까지 | 출하 계통 **3곳에 각각 재적용**(patch-id 전부 상이), 장비 완료 후 **5.5개월** |
| `moana` 출하본에 없는 커밋 | **712 / 5,705 (12%)** — OEM·국가·인증 329 · 기술·기능 207 · 단종라인 142 |
| 장비·앱이 같은 값을 다른 이름으로 | **41건** (같은 이름·다른 값은 0건) |

| 시나리오 (**투영**) | 지금 | 목표 |
|---|---|---|
| PW 파라미터 1건 추가 | 장비 6파일 + 프로토콜 3벌 + 앱 2벌 | **3곳** |
| 측정 도구 추가 | `scan_controller.dart` **8,354 LOC** 수정(sonex) | feature 1개 |
| 새 모델 지원 | 컴파일 플래그 + 모델별 별도 빌드 | **런타임 설정 1건** |
| 고쳤는지 확인 | 실장비 연결 → 수동·사내 QA | 개발 PC E2E |

> **구조로 풀리지 않는 것을 먼저 뺀다** — 인증 브랜치·단종 라인·Qt6 이행은 리팩토링 대상이 아니고, `belle-fw` 의 미도달 33%는 별도 제품라인과 진행 중 R&D 라 **구조 문제가 아니다**. 릴리스 재출시 문제는 그들이 2022년에 이미 고쳤다. 상세 = [../review/change-cost.md](../review/change-cost.md) §2.1·§3·§5.

## 힐세리온이 얻는 것

| | 실측 |
|---|---|
| **멈춘 일이 끝난다** | Qt→Flutter 전환 2년 3개월간 **도메인 이식 0건**이고 구 계층은 1년에 4.6배 · 장비 밑단 2021년 동결 |
| **데이터 경로 회귀 판정이 자동화된다** | 지금은 사내 QA(`[SQA]` 150건)와 고객 신고로 잡는다. **다만 효과 범위는 좁다** — 최근 회귀 표본에서 E2E 가 닿는 것은 **25%**, 44%는 QML UI 라 못 잡는다([../review/change-cost.md §7](../review/change-cost.md)) |
| **같은 일을 여러 번 하지 않는다** | Power Doppler 1건이 출하 계통 **3곳에 각각 재적용**됐고 patch-id 가 전부 다르다 |
| **출시가 빨라진다** | 모델별 빌드 → 단일 이미지. CE/US 뒤바뀜 출하 사고가 구조적으로 제거 |
| **규제 산출물이 부산물로 생긴다** | 62304 구성관리·SOUP·검증기록 = CI·의존성 관리의 결과물 |
| **지식이 저장소에 남는다** | 지금 빌드 절차는 특정 디렉토리 배치(`/home/jacob/...`)에 들어 있고 `belle-fw`·`belle-bsp`·`belle-msp` 에 README 0건 |
| **작업 처리량이 인원에서 풀린다** | cctv 는 같은 조건을 갖춘 뒤 **2026년 커밋의 91% 를 AI 에이전트가 처리**한다. 인원을 늘리지 않고 처리량을 올리는 경로는 이것뿐이다 |

상세 = [why.md](why.md) · 선례 실측 = [precedent-cctv.md](precedent-cctv.md)

**힐세리온이 던질 반론**(의료기기 규제 · AI 가 고쳐도 안전한가 · 우리가 하면 된다 · 실패하면)에 대한 답은 [why.md §11](why.md) 에 있다.

| 항목 | 이유 |
|---|---|
| **~~프로토콜 정본 단일화~~ → 산출물 완성.** 남은 것은 힐세리온 승인 | 정본 1벌·검증기·재현 절차 = [proof/protocol-sot/](proof/protocol-sot/). 원본 3벌과 바이트 배치 동일 · 원본 철자 198개 값 보존 · 동작 보존을 **컴파일러가 판정**한다 |
